# 车机悬浮球「迷你版」技术设计文档（方案③：自研 + 参考交互重绘 UI）

> 版本：v1.0（设计稿，未含代码）
> 目标设备：2022 款吉利几何 E 车机中控（**Android 9 / API 28，横屏**）
> 运行环境锁定：仅面向车载 Android 9，不兼容安卓 7/8，也不追高 targetSdk（详见 §3.4、§5、§10）。
> 设计原则：单一 App、无广告、不联网、轻量、横屏适配、合法合规（MIT 底子 + 自绘 UI，不复制任何闭源代码/资源）

---

## 1. 背景与目标

### 1.1 使用场景
- 车机桌面会隐藏部分已安装 App 的图标，用户无法从桌面直接打开。
- 车机中控无实体/常驻虚拟导航键，缺少「返回 / 主页 / 多任务」入口。
- 中控为横屏，多数手机向悬浮球 App 在横屏下 UI 异常。
- 市售商业悬浮球 App（EasyTouch / Easy Softkey / 客连通等）均内置广告变现（穿山甲、广点通、推送广告、积分墙），不符合"干净"诉求。

### 1.2 产品目标
做一个**单一、无广告、轻量**的悬浮球工具，在车机上提供：
1. 常驻可拖拽悬浮球；
2. 点球弹出面板，含「常用程序」宫格（自选启动任意已安装 App，含被桌面隐藏的）；
3. 安卓三大金刚键：返回(Back)、主页(Home)、多任务/最近(Recents)；
4. 横屏良好适配；
5. 开机自启 + 被杀复活（车机常驻）。

### 1.3 非目标（明确不做）
- 不做主题商店、积分墙、金币、推送、统计、任何联网功能；
- 不做截图、录屏、相机等重权限功能；
- 不逆向/不复制任何闭源商业 App 的代码或美术资源。

### 1.4 分期策略（V1 无障碍已实测通过，Phase 2 解锁）
- **Phase 1（不依赖无障碍）**：悬浮球 + 常用程序启动 App + 横屏 + 保活 + 设置页。只需悬浮窗权限。
- **Phase 2（V1 已通过，可启动）**：三大金刚(Back/Home/Recents) + 面板下排金刚行 + 无障碍权限引导。
- **实测更新**：已在讯飞车机确认三大金刚无障碍可用（V1 ✅）、悬浮窗可启动（V3 ✅）→ Phase 2 前置门槛已解除。当前**唯一未定项为开机自启/保活（V4）**，需隔夜存活实测。

## 3. 技术选型与复用策略

### 3.1 复用底子（均为 MIT，已核实）
| 底子 | 仓库 | 复用什么 | 已核实要点 |
|---|---|---|---|
| A：12-Grid-Ball | `8373907/12-Grid-Ball` | 悬浮球 Overlay、拖拽/贴边/半透明隐藏/防烧屏、12 宫格启动 App、**横屏尺寸按短边计算** | MIT；minSdk 24；无网络权限；Java |
| B：Assistive Menu Tool | `joaohouto/assistive`（F-Droid `com.joaohouto.assistivemenutool`） | AccessibilityService 对 Back/Home/Recents/Lock 等系统动作的封装、悬浮窗+无障碍双权限引导 | MIT；无广告/无网络/无统计 |

### 3.2 自写部分
- 把 B 的"系统动作"作为三个格子接入 A 的面板（Back/Home/Recents）；
- 三大金刚面板接入（返回/主页/多任务 = Back/Home/Recents 全局动作，无系统应用管理页）；
- 面板 UI 重绘：参考竞品排布（上排快捷宫格、下排三大金刚），图标自绘/可商用图标库；
- 设置存储、开机自启、保活复活逻辑；
- 车机横屏/保活专项调优。

### 3.3 明确不采用
- **逆向提取闭源商业包**：混淆剥离成本高、产物脏、且复制闭源代码/资源有著作权风险。
- 理由：三大金刚与启动 App 均为安卓公开 API，逆向无信息增量。

### 3.4 工程基线
- 语言：Java（与底子 A 一致，降低合并成本）；如团队偏好可换 Kotlin，但合并成本略增。
- 构建：Gradle + AndroidX；**minSdk 26 / targetSdk 28 / compileSdk 28**，只针对安卓 9 车机，不再兼容安卓 7/8，相应删除低版本兼容分支。
- 主工程策略：**以底子 A 为宿主工程**，将 B 的 AccessibilityService 模块移植进来；统一改包名、资源加前缀避免冲突。

### 3.5 ABI 与包体策略（求稳求小）
- **决策（已定）：不设置 `abiFilters`，保持 universal 包。**
- 依据：本项目为纯 Java + AndroidX，底子 A/B 均**不含任何 `.so` 原生库**，APK 体积与 ABI 无关、天然极小（远低于 N2 的 5MB）；不加过滤时 32/64 位车机都能装，兼容性最高。
- 补充：安卓 9 ≠ 一定 64 位，部分吉利/廉价车机 SoC 为 armeabi-v7a；正因如此，锁 `arm64-v8a` 反而有装不上的风险，故默认不筛选最稳。
- 例外（暂不适用）：仅当将来引入带 `.so` 的第三方依赖时，再据 §8-V0 的 ABI 实测结果决定是否加过滤（确认 64 位可锁 `arm64-v8a`，不确定则保留 `armeabi-v7a` + `arm64-v8a`）。

## 4. 总体架构

### 4.1 组件划分
| 组件 | 类型 | 职责 |
|---|---|---|
| FloatingBallService | 前台 Service + WindowManager Overlay | 悬浮球与面板 UI、拖拽/贴边/隐藏、点击分发 |
| NavAccessibilityService | AccessibilityService | 执行 GLOBAL_ACTION_BACK / HOME / RECENTS —— **Phase 2 才引入** |
| SettingsActivity | Activity | 配置常用 App、球参数、权限引导入口 |
| PermissionGuideActivity | Activity | 引导开启悬浮窗（Phase 1）+ 无障碍（Phase 2）两项手动权限 |
| BootReceiver | BroadcastReceiver | 接收 BOOT_COMPLETED，开机拉起 FloatingBallService |
| ReviveScheduler | AlarmManager/JobScheduler | 检测服务被杀后复活 |
| PrefsRepository | SharedPreferences 封装 | 持久化常用 App 列表与球参数 |

### 4.2 数据流与通信
- 面板格子点击 → 判断类型：
  - App 格：`PackageManager.getLaunchIntentForPackage(pkg)` + `FLAG_ACTIVITY_NEW_TASK` → startActivity；
  - 金刚格：通知 NavAccessibilityService 执行对应 `performGlobalAction(...)`。
- FloatingBallService 与 NavAccessibilityService 通信：采用**静态单例 + 回调**（最简单）或 LocalBroadcast；文档定调为静态单例持有 AccessibilityService 引用，空则提示"未开启无障碍"。
- 配置读写统一走 PrefsRepository，Service 与 Activity 共享。

### 4.3 生命周期与保活
- FloatingBallService 以**前台服务**运行（startForeground + 低打扰通知），提升车机存活率；
- BootReceiver 开机自启；
- onTaskRemoved / 服务意外销毁时，由 ReviveScheduler 延迟重启；
- 无障碍服务若被车机回收，面板金刚格点击时检测并引导重新开启。

## 5. 关键实现要点（逐功能，仅设计不含代码）

### F1 悬浮球
- 用 WindowManager 添加 Overlay View；窗口类型统一用 `TYPE_APPLICATION_OVERLAY`（安卓 9 原生支持，已删除安卓 7/8 的 `TYPE_PHONE` 兼容分支）。
- 标志位：`FLAG_NOT_FOCUSABLE`（不抢输入焦点）+ 不拦截面板外触摸按需。
- 拖拽：onTouch 记录位移，实时更新 LayoutParams 坐标；松手做贴边动画到最近屏幕边。
- 隐藏：N 秒（默认 3s）无操作降低 alpha 或收为半透明扇形；防烧屏：隐藏态每分钟微调 1px 位置。
- 横屏尺寸：球直径与面板宽度按**屏幕短边**比例计算（沿用底子 A 的 v1.1 修复思路）。

### F2 弹出面板
- 面板为第二个 Overlay View（或 PopupWindow），锚定球位置展开；超出屏幕边时自动翻转方向。
- 布局：顶部标题行 + 设置齿轮；中部宫格（RecyclerView/GridLayout，横向可翻页）；底部固定一行三大金刚。
- 点击面板外区域收起面板。

### F3 启动任意 App（含被隐藏的）
- 枚举可启动 App：`queryIntentActivities(Intent(ACTION_MAIN, CATEGORY_LAUNCHER))` 得到已安装可启动列表（被桌面隐藏但已安装的 App 仍在此列，除非系统级 disable）。
- 设置页勾选/搜索/排序，存入 PrefsRepository（pkg 名序列）。
- 面板 App 格点击：`getLaunchIntentForPackage(pkg)`，加 `FLAG_ACTIVITY_NEW_TASK` 启动；intent 为 null 时 toast 提示。
- 读应用列表：安卓 9 (API28) 不存在 Android 11+ 的包可见性限制，targetSdk=28 下 `queryIntentActivities` 可直接枚举全部可启动 App，**无需 QUERY_ALL_PACKAGES**。

### F4 三大金刚（核心，依赖无障碍）—— **Phase 2，待车机确认无障碍后实现**
- NavAccessibilityService 继承 AccessibilityService，在 onAccessibilityEvent 无需做事，仅暴露执行方法。
- 动作映射：
  - 返回 → `performGlobalAction(GLOBAL_ACTION_BACK)`
  - 主页 → `performGlobalAction(GLOBAL_ACTION_HOME)`
  - 多任务 → `performGlobalAction(GLOBAL_ACTION_RECENTS)`
- 未开启无障碍时：金刚格点击 → 跳 `Settings.ACTION_ACCESSIBILITY_SETTINGS` 引导开启；并在设置页提供一键跳转。
- 车机若无无障碍设置入口：提供 ADB 预授权命令文档（`settings put secure enabled_accessibility_services <pkg>/<service>`），见 §8 V1。

### F5 边界澄清：无「任务管理器」功能
- 经与用户确认，**需求自始不含任务管理器/系统应用管理页**；面板底部只有三大金刚（返回/主页/多任务）。
- "多任务" = `GLOBAL_ACTION_RECENTS`（最近任务概览屏），只做"切换 + 上滑划掉最近任务"，**不是**电脑式任务管理器，不含强制停止/查看内存。
- 明确**不接入** `ACTION_MANAGE_APPLICATIONS`（原生 Android 8 起弱化、车机常裁剪）；代码中 `performTaskManager`/`NAV_TASK_MANAGER`/`task_manager_mode` 等被带偏时留下的残留命名已一并清除。

### F6 横屏适配
- 不锁 screenOrientation，跟随系统当前方向；
- 所有尺寸（球直径、面板宽高、宫格列数）按短边 dp 换算；
- 方向变化时重算 LayoutParams 并重新贴边；
- 车机实测横屏 + 模拟竖屏双测。

### F7 保活与开机自启（安卓 9 重点）
- **安卓 9 后台启动限制**：targetSdk≥26 后，非前台状态下 `startService` 会被系统限制，必须用 `Context.startForegroundService()`，且服务须在启动约 5 秒内调用 `startForeground()`，否则被杀/抛异常。FloatingBallService 全程按前台服务方式启动。
- 前台服务 + 通知（通知可设为最低重要性，减少打扰），提升车机存活率；
- BootReceiver 监听 `BOOT_COMPLETED`：开机属受限场景，同样用 `startForegroundService` 拉起；
- ReviveScheduler：服务 onDestroy/onTaskRemoved 时排一个几秒后的 AlarmManager/JobScheduler 重启；
- 申请 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 并引导用户在车机"自启管理/电池优化"白名单加本应用（若车机提供）。

### F8 设置页
- 常用 App 管理：列表（图标+名称+勾选）、搜索、上移/下移排序；
- 球参数：大小滑块、透明度滑块、默认贴边位置；
- 权限状态卡片：悬浮窗(已开/未开)、无障碍(已开/未开)，各带跳转按钮。

## 6. 权限与 Manifest 配置清单（仅清单，不含代码）

### 6.1 申请的权限（最小集）
| 权限 | 用途 | 授权方式 |
|---|---|---|
| SYSTEM_ALERT_WINDOW | 悬浮球/面板 Overlay | 手动（设置-显示在其他应用上层） |
| （无障碍）BIND_ACCESSIBILITY_SERVICE | 三大金刚 | 手动（设置-无障碍）—— **Phase 2 才申请/引导** |
| RECEIVE_BOOT_COMPLETED | 开机自启 | 安装时 |
| FOREGROUND_SERVICE | 前台保活 | 安装时 |
| VIBRATE（可选） | 点击反馈 | 安装时 |
| REQUEST_IGNORE_BATTERY_OPTIMIZATIONS（可选） | 车机保活，免被休眠策略杀死 | 弹窗授权 |

### 6.2 明确不申请
INTERNET、ACCESS_NETWORK_STATE、读写外部存储、READ_CONTACTS、READ_CALL_LOG、CAMERA、ACCESS_FINE/COARSE_LOCATION、READ_PHONE_STATE。
（不申请 INTERNET 从根上杜绝广告 SDK 联网与隐私上报。）

### 6.3 Manifest 组件声明要点
- application 下声明：FloatingBallService（foregroundServiceType 可选）、NavAccessibilityService（带 accessibility-service 的 meta-data 指向配置 XML）、SettingsActivity、PermissionGuideActivity、BootReceiver（intent-filter: BOOT_COMPLETED）。
- NavAccessibilityService 需 `android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE"` 与 intent-filter `android.accessibilityservice.AccessibilityService`，并配 accessibility 配置 XML（声明 canPerformGestures 不需要、仅需要全局动作能力，accessibilityFlags 取默认即可）。
- 不声明任何广告/推送 receiver、不声明网络相关组件。

> **分期与验证关系（实测后更新）**：V1 无障碍、V3 悬浮窗、V2 装包、V0 ABI 均已实测✅ 通过→ **Phase 1 与 Phase 2 前置条件均解除**。V1 不再是阻塞项，三大金刚可以开工。**当前唯一未定项：V4 开机自启/保活**，需隔夜 + 重启实测；若车机不允许自启，需依靠白名单 + 前台服务 + ReviveScheduler 复活兼容。

### 8.1 V1 无障碍 ADB 预授权标准操作（实测于讯飞车机）

> **实测背景**：目标车机（几何 E）已内置讯飞车载语音，占用无障碍设置项：
> `adb shell settings get secure enabled_accessibility_services`
> → `com.iflytek.autofly.voicecoreservice/com.iflytek.autofly.access.service.AccessibilityServices`
> 结论：① 车机系统**支持无障碍服务**（V1 底层能力通）；② 该 secure 设置项为**整条覆盖式**，第三方服务必须**追加**写入，切勿直接 put 覆盖，否则会顶掉讯飞语音导致车机语音助手失效。

**关键约束（必须遵守，否则踩坑）**
1. **只能追加、不能覆盖**：`enabled_accessibility_services` 是用 `:` 分隔的多服务列表；写入前必须先 `get` 读出原值，把 MiniTouch 用 `:` 拼到原值后面再 `put`。
2. **组件名必须用「短形式」**：即 `com.lawliet.minitouch/.accessibility.NavAccessibilityService`（`.类名` 相对写法）。原因：[NavAccessibilityService.isEnabledInSettings()](../app/src/main/java/com/lawliet/minitouch/accessibility/NavAccessibilityService.java) 用 `ComponentName.flattenToShortString()` 做字符串比较——若写成完整形式，系统仍能识别服务，但 **App 内状态卡会误报「未开」**。系统的 `unflattenFromString` 对短/完整两种形式都兼容，故短形式两端皆对。
3. **命令整体加双引号**：防止 shell 吞掉 `:` 与 `.`。
4. **同时置 `accessibility_enabled 1`**：仅写服务列表不够，该开关须为 1 系统才真正启用（讯飞在用时多半已是 1，补写无害）。

**操作步骤**
```bash
# ① 读原值并备份（用于异常恢复）
adb shell settings get secure enabled_accessibility_services
#   记录：com.iflytek.autofly.voicecoreservice/com.iflytek.autofly.access.service.AccessibilityServices

# ② 追加 MiniTouch（讯飞在前、用 : 连接、短形式、整体加引号）
adb shell settings put secure enabled_accessibility_services "com.iflytek.autofly.voicecoreservice/com.iflytek.autofly.access.service.AccessibilityServices:com.lawliet.minitouch/.accessibility.NavAccessibilityService"
adb shell settings put secure accessibility_enabled 1

# ③ 读回验证两条是否都在
adb shell settings get secure enabled_accessibility_services

# ④ 拉起进程并看服务是否 connected
adb logcat -s NavA11yService   # 期望打印 "accessibility service connected"
```

**结果判定**
- **实测结论（几何 E 讯飞车机）：V1 通过**——无障碍三大金刚（Back/Home/Recents）均可用，悬浮球（V3）也能启动；说明该 ROM 允许第三方无障碍服务共存（与讯飞语音互不顶掉）→ Phase 2 可以开工。
- ③ 能读到 MiniTouch 那条 **且** ④ 出现 `accessibility service connected` → **V1 通过**，`NavAccessibilityService.isReady()` 为真，可启动 Phase 2（三大金刚）。
- 写进去、读回却只剩讯飞那条 / MiniTouch 消失 → 讯飞车机 ROM **仅允许白名单服务**，第三方无障碍被过滤 → 改走系统设置界面手动勾选；界面亦无入口则 V1 判不通过，三大金刚需求按本文「不通过对策」调整。

**异常恢复（若误覆盖导致讯飞语音失效）**
```bash
adb shell settings put secure enabled_accessibility_services "com.iflytek.autofly.voicecoreservice/com.iflytek.autofly.access.service.AccessibilityServices"
```

### 8.2 车机实测设备画像与结论（几何 E / ac8x_demo）

> 采集方式：一次性**只读**采集（`getprop`/`wm`/`dumpsys`/`settings get`/`ps`/`pm list`），未修改车机任何设置；原始输出存档于 `~/car_probe_20261016_2048.txt`。

**A. 系统平台**
- Android 9 / API 28（`ro.build.version.release=9`、`ro.build.version.sdk=28`）→ 与项目 `targetSdk=28` 前提**完全吻合**。
- SoC：`autochips`（杰发科技车规芯片），`ro.product.model=ac8x_demo`。
- build：`full_ac8x_demo-userdebug 9 PI ... test-keys` → 本机（真实量产车）固件为 `userdebug`+`test-keys` 的 autochips 公版 BSP（厂商基于芯片方案商公版固件出货、未重编 user 版），权限较宽松、USB 调试可直接开启。
- ABI：`arm64-v8a,armeabi-v7a,armeabi`（64 位为主、兼 32 位）→ **保持 universal 包，不加 `abiFilters`**（与 §7 ABI 决策一致）。
- Launcher：`com.haoke.launcherapplication`（priv-app 定制桌面）。

**B. 屏幕与显示（V5 定论）**
- `Physical size 1920×720`、`Physical density 160`(mdpi)；**短边 = 720** → 悬浮球/面板按短边 720 换算自适应。
- `mUserRotationMode=USER_ROTATION_LOCKED`、`mCurrentRotation=ROTATION_0`、`mOrientationSensorEnabled=false` → **方向锁死横屏、不随传感器旋转**，**无需处理横竖屏切换**（比原设计假设更简单）。
- 系统栏：存在 **CarNavigationBar**（车载导航栏）+ **StatusBar**。
  - → 悬浮球默认落点（左中贴边）**需避开系统栏区域**，防遮挡；
  - → 车机自带导航栏可能已含 Back/Home/Recents，三大金刚作为**悬浮快捷入口仍有价值**，但非唯一入口。

**C. 电源与后台（V4 相关）**
- `screen_off_timeout ≈ 1879048191ms`（约 21.7 天）→ **近乎永不息屏、屏幕常亮**：利于悬浮球常驻可见；但**需启用防烧屏**（半透明隐藏/微位移，复用底子 A 能力）。
- `deviceidle whitelist`：仅系统包（calendar/downloads/shell/contacts），**无第三方**；但常亮不息屏 → Doze 基本不触发，后台限制影响小。
- 第三方生态开放：已装 `com.oushang.carlink`、`net.easyconn`（亿连）、`com.shihab.diplay`、`com.autonavi.amapauto`（高德）、`com.baidu.netdisk.car`、`com.gosuncn.toolsInstall` 等。
- `BOOT_COMPLETED` 静态注册：后装第三方（carlink/diplay/geometry_car）均能注册进派发列表；无专门自启拦截管家（仅 `com.adayo.carmanager` 车控）。
- carlink 采集时刻在运行（`u0_a46 pid=10494 S com.oushang.carlink`）→ **弱正向**，但非「开机自启」确证（可能手动启动/用完不退）。

**D. 风险与待办**
1. ⚠️ **本机固件权限较宽松（`userdebug`+`test-keys`）**：可较自由地用 adb 授权/调试，但 **App 内仍必须走正规授权路径（无障碍授权/悬浮窗申请/BootReceiver），不得依赖 root 或 userdebug 的宽松性**，以兼容其他可能采用 `user` 版固件的车机。
2. ⏳ **V4 确定性验证**：下次装 MiniTouch/最小探针 → `adb reboot` → `ps -A | grep minitouch` 一锤定音。
3. 悬浮球落点需实测避开 CarNavigationBar / StatusBar。
